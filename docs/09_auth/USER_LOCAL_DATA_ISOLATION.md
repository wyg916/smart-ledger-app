# 用户本地数据隔离与 Schema 4 绑定

状态：FROZEN
选择：每个 `user_id` 独立 SQLite 文件（方案 A）

## 选择理由

现有 Schema 4 的账本、账户、分类、交易、预算和事件队列均围绕单账本外键设计。逐表增加
`owner_user_id` 会扩大所有 Repository、查询、索引和迁移的遗漏风险。独立数据库文件可在文件边界阻止
跨账号查询，并让现有业务约束保持不变。

## 文件与生命周期

- 文件名为 `smart_ledger_<sha256(user_id)前24位>.sqlite`，不含手机号、微信身份或完整 user_id。
- 未认证时不得打开用户数据库；认证 user 改变时关闭旧连接，再创建新 Provider 图。
- 退出登录只关闭数据库并清除 token，不删除账本；下一账号只能打开自己的文件。
- 注销账号时按用户明确选择删除该文件或保留为不可访问的隔离文件。

## 现有开发账本

旧文件 `smart_ledger.sqlite` 永不静默移动、删除或上传。首次正式登录且目标用户文件不存在时展示：

1. “绑定现有本地账本到此账号”：复制到临时文件、原子改名为用户文件，旧文件保留；重复执行不覆盖。
2. “使用全新账本”：记录该用户决定并创建新的 Schema 4/后续版本数据库。

绑定完成后 Drift 按正常迁移链打开，必须验证账本、账户、分类、交易、预算和事件数量保真。绑定标记只
保存不可逆 user 文件键，不保存认证 Provider 信息。业务账单不上传服务器，也不构成云备份。

## 最低测试

- user A 写入后切换 user B 不可读取；再次登录 A 可恢复。
- 退出后所有业务页面不可见，数据库连接被释放。
- Schema 4 复制绑定保留数据且幂等；“全新账本”不修改旧文件。
- 文件键确定、不可由手机号/微信推导；路径遍历字符不能进入文件名。
