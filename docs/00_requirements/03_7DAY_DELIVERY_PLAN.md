# 1. 执行结论与一周目标定义
| 可行性结论<br>按照原技术架构文档的完整范围，2 人激进 MVP 仍需约 12-16 周；从当前 Android 离线 MVP 出发，一周内完成完整 Flutter 双端、完整云同步、旧数据迁移、全部统计预算、安全加密、AI、双商店公开上线并不现实。要执行 7 日目标，必须采用 6-8 人并行冲刺、强制裁剪范围，并把“上线”拆成技术上线、内测上线、商店提交和商店公开四个层级。 |

## 1.1 7 天必须交付的结果
- 一个可在 Android 与 iOS 真机安装运行的 Flutter MVP。
- 一个已部署到生产云环境的 FastAPI + PostgreSQL 后端，具备健康检查、数据库备份、基础监控。
- 本地模式：不登录也能完成记账、账单查看、分类、基础统计和预算。
- 云同步模式：登录后可完成单用户、单账本的增量上传、拉取、软删除和断网重试；禁止静默覆盖交易。
- AI 增强：支持限定问题的财务问答与储蓄目标规划；不做 RAG、记忆系统、Agent 或任意 SQL。
- Android 生成正式签名 AAB 并上传 Play Console 内测/封闭测试；iOS 生成 Archive 并上传 TestFlight。
- 完成 App Store / Google Play 商店资料、隐私政策、权限披露、截图和提交动作。
- 形成上线后监控、回滚、缺陷处理与 V1.0.1 Backlog。

## 1.3 冲刺成功判定
| 维度 | 成功标准 |
| --- | --- |
| 核心业务 | 收入/支出新增、编辑、删除、分类、账单列表、月份切换、首页汇总全部可用。 |
| 本地能力 | 断网状态下核心记账流程可运行；重启后数据不丢失。 |
| 云同步 | 新增/编辑/删除可跨两台设备同步；重复提交不重复；冲突不得静默覆盖。 |
| AI | 支持固定意图问答与目标规划；金额由确定性代码计算；模型不可用时核心 App 不受影响。 |
| 安全 | 凭证、Token、金额、备注不进入普通日志；生产 Secret 不进入仓库。 |
| 质量 | P0/P1 缺陷为 0；关键 E2E 全部通过；双端至少各 2 台真机完成冒烟。 |
| 发布 | 生产后端、AAB、iOS Archive、TestFlight、Play 内测/封闭测试及商店材料完成。 |

## 2.1 人力假设
| 方案 | 团队配置 | 7 日可交付范围 | 结论 |

| 推荐 | 6-8 人：产品/架构 1、Flutter 2、后端/数据 1-2、QA/DevOps 1、设计/发布合规 0.5-1 | 本文定义的 MVP RC + 双端内测 + 商店提交 | 可执行但风险高 |
| 最低 | 4-5 人：Flutter 2、后端 1、技术/产品 1、QA/发布 1 | 需再裁剪预算/AI/完整冲突处理中的至少一项 | 勉强可执行 |

## 2.2 存量用户决策
- 无真实用户：可跳过旧 Android 原地升级桥接，直接以 Flutter V2 数据模型上线。
- 有真实用户且需要覆盖升级：旧 Room/DataStore 导入、包名、签名和逐月金额对账必须列为 P0；必须从 AI 或预算等功能中裁剪工作量。
- 原签名丢失：不能作为原应用升级，只能发布新应用并通过备份文件迁移；不得宣称无损升级。
# 3. 首发 MVP 范围与延期清单
## 3.1 一周内纳入的 P0/P1 功能
| 模块 | 一周首发范围 | 验收口径 |
| --- | --- | --- |
| 启动与导航 | 启动安全门、首页/记账/账单/AI/我的主导航、浅色主题 | 双端无白屏；锁定前不展示财务内容 |
| 本地记账 | 收入、支出、编辑、软删除、金额/分类/时间/备注 | 断网可用；重启不丢；核心流程≤3步 |
| 账单 | 月度列表、日期分组、月份切换、交易详情 | 金额/数量与 Fixture 对账一致 |
| 分类 | 默认分类、新增、编辑、排序、禁用 | 已引用分类不可物理删除 |
| 首页统计 | 本月收入、支出、结余、Top 分类 | 统计与交易明细一致 |
| 预算 | 总预算或单一月预算、使用进度 | 边界金额正确；无复杂提醒系统 |
| 账号 | 手机号验证码登录；退出保留本地数据 | 限流、过期、错误提示可用 |
| 云同步 | 单用户单账本，Bootstrap、Push、Pull、Outbox、软删除、退避 | 双设备新增/改/删通过；重复提交幂等 |
| 冲突 | 版本检查；交易冲突保留副本并提示，不静默覆盖 | 冲突 Fixture 通过 |
| AI问答 | 消费原因、分类排行、月度收支、预算状态等白名单问题 | 只使用结构化指标；模型无数据库直连 |
| AI规划 | 储蓄目标、目标金额、期限、月度缺口和建议 | 金额由确定性计算器生成 |
| 安全/隐私 | Secure Storage、Token 轮换、最小日志、HTTPS、Secret 管理 | 日志抽查无敏感数据 |
| 发布 | 生产后端、AAB、Archive、TestFlight、Play 内测/封测、商店提交 | 构建可重复；资料完整 |

- P0/P1 缺陷未清零，或双端任一端无法稳定安装/启动。

- 先内部测试，再封闭测试/分阶段发布；异常立即停止扩大范围。

## 10.1 功能降级顺序
1. 先降级高级视觉、动画、图表和非必要设置。
2. 再延期预算、AI月度总结等 P1 功能；保留 AI问答/规划的最小入口。
3. 再将云同步降级为“登录后云备份/单设备恢复”，但必须明确不支持多设备实时同步。
4. 任何情况下不得降级金额准确性、本地数据持久化、同步防丢失、认证安全和隐私。
